# M9.20 chain-walk route 3: the map the *third* level change out of
# ohl_campaign::STARTMAP ("c0a0") lands in, walked from its arrival point.
#
# Project-authored; no bytes here come from any game installation (see
# docs/CLEAN_ROOM.md). Named by its position in the chain rather than by
# the map it runs on, for the reason recorded in c0a0-hop1.txt and in
# xtask/src/chain_walk.rs's module documentation.
#
# A line's leading number is a count of *ticks*, each one CAPTURE_STEP
# (1/60 s) of simulated time — not seconds.
#
# Route, in words only (no entity name, path or coordinate from any
# payload): the player presses nothing at all, and this route's whole
# content is waiting for the map to run its own scripted ride, which ends
# by firing a level change by name — the same shape c0a0-hop2.txt ends on,
# and where `run_chained` ends the route.
#
# The player is a passenger for the whole of this route. A per-tick probe
# of `PlayerState::ground_brush` puts them on a `func_tracktrain` for
# 4015 of its 4016 ticks (the missing one is the level-change tick
# itself). It was 0% when this file was written, 91.5% after M9.23 settled
# the spawn aboard the opening ride, and 100% since M9.25 started carrying
# a rider's seat relative to the ride rather than as a raw landmark
# offset — see docs/MILESTONES.md M9.25 and docs/FORMAT_SOURCES.md,
# "Riding movers".
#
# M9.19 could not get here at all. Two separate faults sealed the arrival
# point at a single reachable cell with no frontier entity of any kind, and
# either one alone was enough to do it:
#
#   - The whole carried ride state was discarded whenever the destination
#     map declared no `path_track` of the carried node's name — which is
#     this boundary — so the destination's own copy of the car ran on its
#     spawn speed instead of arriving parked as its map is authored around.
#   - This map — alone among the four the chain has entered — starts its own
#     copy of the ride with a `trigger_auto` that declares the documented
#     `triggerstate` keyvalue as "On", and this port read every fire as a
#     plain toggle, so the one thing in the map whose job is to *start* the
#     car switched it off instead.
#
# A third fault surfaced once the ride ran: a door group standing across the
# tunnel reported itself open while its collision hull sat closed, because a
# mover carried across a level change overwrote the destination map's own
# compiled keyvalues instead of only its state.
#
# See docs/MILESTONES.md M9.20, and docs/FORMAT_SOURCES.md "Entity keyvalues
# and map logic" (`trigger_auto`) and "Campaign flow".
#
# M9.21 closed the gap M9.20 recorded here: the second door group near the
# end of the loop used to finish closing about four seconds before the car
# reached it. A multi_manager that three identical trains all re-fired ran
# three copies of its schedule instead of ignoring the re-fires, and the
# ride was released from its scripted halt at the crawl its braking nodes
# had left it at rather than at its own speed. See docs/MILESTONES.md
# M9.21 and docs/FORMAT_SOURCES.md (multi_manager; "Track trains and
# paths").
#
# Known gap: the passenger is lost in the transition *into* this map, so
# the ride runs the loop with nobody aboard and the level change it fires
# by name still ends the route.
#
# The trailing wait is slack: `run_chained` (crates/ohl-app/src/game_run.rs)
# ends a route at the level change it reaches, so any ticks left over here
# are never run.
