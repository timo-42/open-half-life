# M9 scripted-input scenario: a spawn-to-exit progression walk in Power
# Up.
#
# Project-authored; no bytes here come from any game installation (see
# docs/CLEAN_ROOM.md). Run against "c2a1" (Power Up, per
# ohl_campaign::CHAPTERS's own cited table) by xtask/src/combat_smoke.rs,
# with `--follow-level-change` so a `trigger_changelevel` this walk
# reaches is actually followed rather than only logged as "not followed".
#
# Route, in words only (no entity name, path or coordinate from any
# payload): from the player's spawn point, advance forward through a long
# sequence of turns, passing near a monster along the way (a source of
# damage to it, not a route failure), until a level change fires; then
# wait out the transition. No door needs opening on this route.
#
# Technique: an autopilot was flown over this map's own collision hulls,
# and the per-tick inputs it applied were recorded and merged into the
# whole/fractional-degree turns below, matching the technique documented
# in xtask/smoke-scenarios/reach_level_change_anomalous_materials.txt.
# Runs whose per-tick turn is not bit-for-bit identical to its neighbor
# are kept as their own single-tick line rather than merged, which is why
# many lines below carry small fractional-degree turns. The run is
# deterministic, so replaying these inputs reproduces the same route
# every time.
#
# Update (M9.10, docs/FORMAT_SOURCES.md item 33): this map carries 29
# `func_monsterclip` entities. Fixing `func_monsterclip` so it is no
# longer solid to the player (the whole point of that milestone) measurably
# changed this route's own physical path under these exact same scripted
# inputs, since the route below was originally flown by autopilot against
# a collision model that (incorrectly) treated `func_monsterclip` as solid
# to the player too. It no longer reaches its `trigger_changelevel` inside
# this script's own step budget, and the monster it passes now lands one
# hit on the player before dying instead of never connecting. Neither is
# treated as a route failure any more; see `xtask/src/combat_smoke.rs`'s
# `POWER_UP_MONSTER_ENCOUNTER_PRESENT`/`_ABSENT` doc comments for the full
# account. Re-authoring this route's steps against the corrected engine
# (the paragraphs below, and the steps themselves) is left as follow-up
# rather than done blind in the same change that fixed the collision bug
# this route exposed.
#
